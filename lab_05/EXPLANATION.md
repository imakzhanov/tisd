# ЛР 5. Как работает программа

В варианте № 2 есть две очереди и один обслуживающий аппарат (ОА). У каждого типа заявок своя очередь FIFO. Когда аппарат свободен, он сначала проверяет первую очередь. Если она пуста, берёт заявку из второй. Если заявка первого типа приходит во время обслуживания второго, она ждёт. Это **относительный приоритет**.

## От меню до модели

`main.c` вызывает `simulate` с параметрами, выбранной реализацией очередей, начальным значением генератора `seed` и функцией вывода статистики. `simulate` проверяет диапазоны, обнуляет результат, вызывает `srand(seed)` и создаёт две пустые очереди. Затем запускается общий цикл `run` из `model.c`. После прогона оставшиеся узлы списка освобождаются, в том числе при ошибке. `simulate` возвращает код выполнения, а статистику записывает через указатель `result`.

## Приход и обслуживание

| Параметр | Тип 1, индекс 0 | Тип 2, индекс 1 |
|---|---:|---:|
| Интервал между приходами, `params->arrival[i]` | от 1 до 5 | от 0 до 3 |
| Длительность обслуживания, `params->service[i]` | от 0 до 4 | от 0 до 1 |

`random_time` получает случайную долю между 0 и 1 и переносит её в заданный диапазон по формуле `min + (max - min) * fraction`. Например, доля 0,25 в диапазоне от 1 до 5 даёт интервал 2.

- В начале `run` часы стоят на нуле. Первый случайный интервал для каждого типа сразу становится временем его первого прихода.
- При каждом приходе программа кладёт в очередь текущее время `now` и планирует следующий приход **того же типа** через `arrival[i] = now + random_time(params->arrival[i])`.
- Длительность обслуживания генерируется, когда аппарат берёт заявку. Он освободится в момент `finish = now + random_time(params->service[i])`.

В массиве `arrival[2]` лежат **моменты ближайших приходов**, а в `params->arrival[2]` — **диапазоны интервалов**. В самом элементе очереди хранится только время прихода конкретной заявки.

## Как устроен аппарат и движутся часы

Состояние аппарата описывают две переменные. `active = -1` означает, что аппарат свободен, `0` — обслуживает первый тип, `1` — второй. `finish` хранит время завершения обслуживания. Пока аппарат свободен, `finish = INFINITY`, поэтому это значение не выигрывает при выборе ближайшего события.

На каждой итерации `run` выполняет следующие действия.

1. Выбирает ближайшее событие через `now = fmin(fmin(arrival[0], arrival[1]), finish)`. Разность `now - result->time` показывает, сколько модельного времени прошло с прошлого события. Программа учитывает этот промежуток в статистике и переводит часы на `now`.
2. Обрабатывает все приходы на этой отметке. Для каждого подходящего типа добавляет заявку в хвост, увеличивает счётчик приходов и назначает следующий приход.
3. Если `finish == now`, засчитывает выход заявки типа `active` и освобождает аппарат.
4. Если аппарат свободен и цель прогона ещё не достигнута, проверяет очереди по порядку. Берёт голову первой непустой очереди, считает ожидание и назначает новое время окончания обслуживания.

Если приход и окончание обслуживания совпали, оба события учитываются до выбора следующей заявки. Часы переходят сразу к событию, поэтому симуляция не ждёт реальных секунд.

### Пример

| Модельное время | Что происходит |
|---|---|
| 3,0 | Аппарат берёт заявку второго типа. Длительность 0,8, поэтому `active = 1`, `finish = 3,8`. |
| 3,2 | Приходит заявка первого типа. Значение 3,2 записывается в её очередь. Аппарат занят до 3,8. |
| 3,8 | Заявка второго типа выходит. Аппарат берёт заявку первого типа. Она ждала 3,8 − 3,2 = 0,6. Если обслуживание займёт 1,5, новый `finish` будет равен 5,3. |

## Из чего состоит результат

`result_t` хранит модельное время `time`, суммарный простой аппарата `idle`, пиковую память двух очередей `queue_memory` и статистику по каждому типу в `queue[0]` и `queue[1]`.

| Поле одной очереди | Что хранит |
|---|---|
| `arrived` | Сколько заявок пришло в систему. |
| `departed` | Сколько заявок завершило обслуживание. |
| `size` | Сколько заявок сейчас ждёт. Заявка в аппарате сюда не входит. |
| `started` | Сколько заявок аппарат взял на обслуживание. |
| `area` | Накопленную сумму длины очереди, умноженной на время. |
| `wait` | Сумму времени ожидания заявок, уже взятых аппаратом. |

Если между двумя событиями очередь из трёх заявок сохранялась две единицы времени, к `area` прибавляется 6. **Средняя длина** равна `area / time`. Когда аппарат забирает заявку, к `wait` прибавляется разность между текущим временем и временем её прихода. **Среднее ожидание** равно `wait / started`. Если на промежутке между событиями аппарат был свободен, весь промежуток прибавляется к `idle`. Время работы аппарата равно `time - idle`.

Каждые 100 выходов первого типа выводится промежуточная статистика. После 1000-го выхода программа останавливается. В итогах `io.c` сравнивает модельное время с расчётом по числу приходов каждого типа. Отдельно сравнивается время работы аппарата с суммой расчётных времён обслуживания по обоим типам. Для расчёта берётся середина соответствующего диапазона, умноженная на число заявок.

## Как хранятся очереди

- **Кольцевой массив, `arr_queue.c`.** `p_in` — индекс следующей записи, `p_out` — индекс следующего извлечения. Индекс после последней ячейки переходит на нулевую через остаток от деления на ёмкость. `size` различает пустой и полный массив, даже когда индексы совпадают.
- **Односвязный список, `list_queue.c`.** `p_in` указывает на последний узел, `p_out` — на первый. При добавлении выделяется новый узел, при извлечении первый узел освобождается. В пустой очереди оба указателя равны `NULL`. При включённом выводе программа показывает адрес узла при добавлении и удалении.

## Как измеряется производительность

`bench.exe` запускает ту же модель по 100 раз для массива и списка. Параметры и начальное значение генератора одинаковые, поэтому очереди обрабатывают одинаковую последовательность событий. Промежуточная печать и вывод адресов отключены. `clock()` измеряет время выполнения, из которого рассчитывается среднее время прогона в микросекундах. Память массива считается по размеру двух структур целиком, память списка — по размеру двух структур и наибольшему суммарному числу одновременно хранимых узлов.

Для разбора кода начни с `simulate`, затем пройди по циклу `run` на примере выше. На каждой итерации выписывай `now`, оба `arrival[i]`, `active`, `finish` и длины очередей.
